# 清洗与抽检方法

从 980 条原始笔记到 217 条入库案例，本文说明规则如何设计、为什么第一版只有 37% 准确率、以及抽检怎么做。

---

## 一、问题定义

要做的是「**某平台的用户负面反馈**」，三个条件必须同时成立：

1. **主体正确**：抱怨对象是目标平台，不是竞品、不是站外商户、不是行业现象
2. **情绪为负**：是受害陈述，不是营销软文、不是提问咨询、不是经验教程
3. **信息充分**：有具体的交易场景与损失，不是一句情绪宣泄

难点在第一条。关键词只能判断「文中出现了平台名」，判断不了「谁在批评谁」。

---

## 二、为什么关键词方案必然失败

第一版规则：正文含平台名 + 含负面词 → 入库。跑出 529 条，抽检准确率 **37%**。

失败样本的四类典型：

| 样本标题 | 关键词命中 | 实际性质 |
|---|---|---|
| 爱回收值耀垃圾平台，避雷 | 爱回收、垃圾、避雷 | 正文讲的是闲鱼纠纷，爱回收只是顺带提了一句 |
| 红布林寄卖翻车实录 | 转转（正文有一句「比转转靠谱」） | 主体是红布林，被归到转转 |
| 没到手刀太爽了，出包顺利 | 到手刀 | **否定式**，语义是正面 |
| 转转上门回收让我改观了 | 压价 | 平台软文，全文在夸 |

核心结论：**词面命中 ≠ 语义负面，提及平台 ≠ 投诉平台**。

## 三、规则体系

### 3.1 主体判定：以标题为准

```python
# 伪代码
title_plats = detect_platforms(title)
body_plats  = detect_platforms(desc)

if title_plats and len(title_plats) == 1:
    platform = title_plats[0]        # 标题唯一平台，直接采信
elif title_plats and len(title_plats) > 1:
    reject("标题多平台")              # 标题混杂，主体不清
elif 正文开头 60 字内点名平台:
    platform = 该平台                 # C 级
else:
    reject("未判定出投诉主体平台")
```

标题里同时出现「爱回收」和「闲鱼」的，多半是对比帖或软文，直接剔除。这一条规则把准确率从 37% 拉到 70% 以上。

评论区的平台提及只作兜底，且仅在正文完全没提时使用（E 级，本批次仅 1 条）。

### 3.2 竞品排除

二奢赛道还有红布林、只二、妃鱼、心上、胖虎等玩家。这些平台的投诉被误归到目标平台，是最隐蔽的污染源。

策略：若标题包含竞品名且不含目标平台名 → 剔除，理由记「竞品主体」。40 条因此被剔除。

### 3.3 软文识别

平台软文有固定的叙事模板，识别特征：

```python
STRONG_POSITIVE = [
    "百家竞价", "不用砍价", "不用拉扯", "到账很快", "没有套路",
    "没有任何套路", "高效", "仪式感", "拉满", "高级感",
    "不压价", "没有压价", "不扯皮", "良心", "改观", "一步到位",
]
# 命中 ≥ 2 个 → 判为平台软文
```

叙事结构上还有一条通用规律：**先踩线下二奢店 → 再夸平台 → 最后「真心安利」**。这个结构可以用「对比软文」标题词辅助识别（「vs」「对比」「还是选了」）。

爱回收的软文密度最高，常见「LUXURY LOUNGE」「吴磊推荐」；转转的常见「竞价模式」「上门回收不压价」。两平台合计剔除 60 条平台软文 + 29 条营销话术 + 15 条商家引流。

### 3.4 否定式识别

```python
NEGATION = ["没", "不", "无", "未", "别"]
# "没到手刀" / "不压价" / "没有想象中坑" → 命中负面词但语义正面
```

规则：负面词前 3 个字符内出现否定词 → 该词不计分。仅这一条就救回 3 条误判。

### 3.5 非投诉类排除

| 类型 | 特征 | 剔除量 |
|---|---|---|
| 提问咨询 | 标题以「吗？」「?」结尾且无强负面 | 1 |
| 教程攻略 | 「防骗锦囊」「维权指南」「教你 3 招」 | 14 |
| 行业观察 | 讨论二奢行业趋势，无具体受害者 | 2 |
| 招聘帖 | 「BOSS直聘」「招聘」「面试」 | 人工剔除 |

### 3.6 噪音词排除

「转转」作为高频词，被大量无关内容命中：

```
转转乐 / 转转鞋 / 旋转 / 转转运 / 转转椅 / 转转门 / 转转杯
转转火锅 / 转转热卤 / 转转小火锅 / 转转串串 / 转转麻辣 / 转转食堂
```

这些必须先剔除，再判断平台归属，否则「盛香亭转转热卤」会被当成转转的投诉。

## 四、分级体系

| 级别 | 判定条件 | 证据强度 |
|---|---|---|
| **A** | 标题含唯一平台名 且 正文负面分 ≥ 3 且（有受害者描述 或 标题含负面词） | 强，可单独引用 |
| **B** | 标题点名平台 + 开头有负面 | 中 |
| **C** | 正文开头点名平台 + 有实质负面 | 中 |
| **D** | 弱负面信号 | 弱 |
| **E** | 正文无抱怨，但评论区集体共鸣 | 弱，需人工判断 |

负面分按维度累加：压价到手刀、质检鉴定、售后维权、欺诈套路、物流损毁、隐私骚扰。每个维度维护独立词表，命中一次计 1 分。

## 五、抽检方法

### 5.1 为什么必须人工抽检

规则是启发式的，能保证**召回**但保证不了**精度**。入库前必须回答：「这批数据里有多少是错的？」

### 5.2 抽样策略

不是随机抽，是**按分级全量核对**。原因：A 级是主力（119 条），错一条影响面大；D 级池子小，抽 12 条的信息量不如全看 59 条。

实际做法（217 条批次）：

| 分级 | 池内 | 方式 | 误判 | 准确率 |
|---|---|---|---|---|
| A | 123 | 全量通读 | 4 | 96.7% |
| C | 42 | 全量通读 | 8 | 81.0% |
| B | 48 | 全量通读 | 12 | 75.0% |
| D | 59 | 全量通读 | 31 | 47.5% |

### 5.3 判定标准

每条看四件事，任一不过即判误判：

1. 说的是不是这个平台（主体）
2. 是不是真负面（情绪）
3. 是不是软文（性质）
4. 负面类型标签标得对不对（分类）

### 5.4 入库门槛

**A/C 级整体准确率 ≥ 85% 方可整级入库**。本批次 165 条中误判 12 条，92.7%，达标。

B/D 级准确率不到 80%，**整级不入库**，改为人工逐条阅读后以白名单形式挑出 64 条真负面。这 64 条是人工确认的，准确率 100%，比规则判定更可靠。

### 5.5 留痕

所有剔除都必须留痕，否则无法复审：

- `reject.jsonl`：692 条，含剔除原因、命中词、候选模块
- `manual_dropped.jsonl`：24 条人工剔除，含具体判断说明
- `cases_hold.jsonl`：47 条待复核

## 六、可复用性评估

这套规则能迁移到其他平台吗？

**能迁移的部分**：漏斗结构（主体判定 → 竞品排除 → 软文识别 → 分级 → 抽检）、否定式识别、留痕机制。

**不能直接迁移的部分**：词表。每个平台的负面表达差异很大——闲鱼的「验货宝」「到手刀」、爱回收的「竞价」「补贴」、转转的「复检」「官换机」，都是平台特有词汇。换平台必须重新做一批标注样本，重跑抽检，看准确率落在哪。

**经验值**：在这类「平台名 + 负面」的舆情任务里，纯规则方案的准确率上限大约 90-93%，再往上要靠 LLM 判读或人工。低于 50% 说明主体判定逻辑有问题，不是词表不够。第一版 37% 就是这个原因。

## 七、脚本说明

| 脚本 | 职责 | 输入 | 输出 |
|---|---|---|---|
| `clean_cases.py` | 主清洗 | 候选池 + 采集正文 + 评论 | `cases_clean.jsonl`、`reject.jsonl`、`stats.json` |
| `finalize.py` | 终裁 | `cases_clean.jsonl` + 黑白名单 | `cases_final.jsonl`、`cases_hold.jsonl` |
| `merge_search.py` | 补搜合并 | 搜索结果 + 旧候选池 | `candidates_v2.jsonl` |
| `sample_check.py` | 分层抽样 | `cases_clean.jsonl` | `sample.txt`、`sample_ids.json` |

`finalize.py` 里的黑名单是人工抽检的结论沉淀，每条都带注释说明为什么剔除。这是整个流程最有价值的部分——它记录了规则拦不住、只有人才能判断的边界情况。
