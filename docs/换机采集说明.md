# 换机采集说明

在另一台电脑上继续补采待采清单，本机通道已被风控降级（2026-11-02 实测）。

## 一、前置

只需要 `python3`（3.8+）和 `curl`，无第三方依赖。

```bash
git clone https://github.com/purehub-space/luxury-resale-sentiment.git
cd luxury-resale-sentiment
python3 -c "import sys;print(sys.version)"
curl --version | head -1
```

> 组织仓库无权限时，用 Gitea 镜像：`git clone https://git.rongdetu.cn/puresnake/luxury-resale-sentiment.git`

## 二、先冒烟，别直接批跑

```bash
python3 collector/run_xhs_guest.py --src pend --limit 2 --interval 5 --max-empty 3
```

- 打印 👍💬🖼 行 = 通
- 打印 `app_only` 连续 3 条 = 这台机器也被降级，停手换网络

## 三、分批跑（建议顺序）

清单已按「建议优先级」排好，`--src pend` 会自动跳过 3C（标记「不做」的 32 条）。

```bash
# 第一轮：P0 三个模块的高优先级（60 条，标题已判二奢）
python3 collector/run_xhs_guest.py --src pend --sug 高 --limit 40 --interval 5 --max-empty 3

# 第二轮：爱回收中优先级
python3 collector/run_xhs_guest.py --src pend --module P0-A-爱回收 --sug 中 --limit 40 --interval 5

# 第三轮：转转
python3 collector/run_xhs_guest.py --src pend --module P0-A-转转 --sug 中 --limit 40 --interval 5

# 闲鱼（已达标，最后做）
python3 collector/run_xhs_guest.py --src pend --module P0-B-闲鱼 --limit 40 --interval 5
```

节奏红线（踩过的坑）：

| 参数 | 建议值 | 原因 |
|---|---|---|
| `--limit` | 单轮 ≤40 | 50–60 条后必降级 |
| `--interval` | ≥5 秒 | 3 秒以下更容易触发 |
| `--max-empty` | 3 | 连续 3 条取不到就熔断，别硬顶 |
| 轮次间隔 | ≥2 小时 | 降级后 12 分钟恢复不了 |

断点续跑：`data/guest/notes_guest.jsonl` 里已有的 note_id 会自动跳过，重复跑不会重复拉。

## 四、常见的空结果含义

| 输出 | 含义 | 处理 |
|---|---|---|
| `app_only` | 被风控降级，网页端不给内容 | 停手冷却，换网络 |
| `no_content` | 页面正常但没有正文（图文/视频特殊排版） | 跳过 |
| `deleted` | 笔记已删除或私密 | 跳过 |
| `no_token` | 链接缺 xsec_token | 脚本会自动从候选清单回填；仍缺则该笔记不可采 |

## 五、数据怎么带回来

新增的全部追加在 `data/guest/notes_guest.jsonl`（每行一条笔记，含正文全文、图片、首屏评论）。

回传方式任选：

```bash
# 方式 A：直接推分支
git checkout -b collect/$(hostname)
git add data/guest
git -c user.name="<你>" -c user.email="<你的邮箱>" commit -m "data: 换机补采 N 条"
git push origin collect/$(hostname)

# 方式 B：只把 jsonl 发回来
# 文件路径 data/guest/notes_guest.jsonl
```

拿到后由本机做入库清洗（品类/负面/回收方式判定 → 案例库），流程见 `pipeline/finalize.py`。
