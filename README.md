# 二手奢侈品回收平台舆情采集

小红书平台上「爱回收 / 转转 / 闲鱼」三个二手奢侈品（下称二奢）回收渠道的用户负面反馈采集、清洗与抽检工程。

从 944 条宽泛召回候选出发，经搜索补采、两级规则清洗、人工分层抽检，最终沉淀 **217 条可入库的负面案例**，每条附原文链接、正文、负面类型标签与评论旁证。

### 字段说明

`outputs/案例库_入库_217条.csv` 共 19 列：

| 列 | 说明 |
|---|---|
| 平台 / 分级 / 入库依据 | 归属平台、证据强度 A-D、规则分级或人工白名单 |
| 标题 / 作者 / 发布时间 | 原帖元信息 |
| 正文摘要 | 正文前 400 字 |
| 负面类型 / 负面关键词 | 六类标签（质检鉴定、欺诈套路、压价到手刀、售后维权、物流损毁、隐私骚扰）及命中的原始词 |
| 点赞 / 收藏 / 评论数 | 采集时点的互动数据 |
| 图片数 / 本地图片 / 图片URL | 原帖图集。**图片 URL 带有时效签名，约 24 小时后失效（实测次日返回 403）**，故已全部下载存档于 `data/images/{note_id}/`，共 950 张（111MB，未随仓库分发） |
| 评论证据 / 评论图URL | 评论区旁证原文（含配图链接） |
| 链接 | 原帖地址 |

`data/clean/cases_final.jsonl` 同样字段，另含正文全文、负面命中词明细、`image_local`（本地已存图片数）等。

### 三家平台的负面特征差异

- **闲鱼**：矛盾集中在**验货宝**——鉴定争议、到手刀、调包、两次鉴定结论不一致，占闲鱼样本六成以上
- **爱回收**：主线是**压价**——线上线下两套报价、以旧换新补贴纠纷、质检报告与实际不符
- **转转**：**复检规则**与**售后**问题突出，另有异常高比例的诈骗类内容（借平台名义引导站外交易）

负面类型分布（入库样本，可多重标注）：质检鉴定 62、欺诈套路 57、压价到手刀 35、售后维权 29、物流损毁 4、隐私骚扰 2。

## 方法要点

完整方法论见 [docs/采集方法.md](docs/采集方法.md) 与 [docs/清洗与抽检方法.md](docs/清洗与抽检方法.md)。三个关键结论：

**一、详情页正文不需要登录，但内容 API 需要。**
小红书笔记页的正文由服务端 SSR 注入 `__INITIAL_STATE__`，游客可见；评论列表接口 `v2/comment/page` 游客也返回 200。但 `v1/feed` 接口对未登录请求返回 `code: -101`。生产环境因此走「登录 + API」，DOM 解析作为兜底。

**二、限流在内容 API 层，与指纹、Cookie 无关。**
同一时段对照测试：无 Cookie、有 Cookie、裸 Playwright、反检测配置，全部被拦。`curl` 直取 HTML 返回 200，但只是空壳。根因是数据中心出口 IP。可行区间是单条间隔 6 秒、每批 40 条、批间冷却 90 秒。

**三、关键词匹配无法判断「谁在批评谁」。**
第一版规则准确率只有 37%，典型误判是「爱回收值耀垃圾平台」实为闲鱼纠纷、红布林案例因文中提了一句「转转」被归到转转。改成**以标题的投诉主体为准**并加入竞品排除、否定式识别、软文识别后，A/C 级准确率升至 92.7%。

## 快速开始

采集依赖 [MediaCrawler](https://github.com/NanmiCoder/MediaCrawler)，需先按 [docs/采集方法.md](docs/采集方法.md) 打三个补丁。

```bash
# 1. 注入 Cookie（浏览器登录后从开发者工具导出 JSON 数组）
mkdir -p ~/.xiaohongshu && cp cookies.json ~/.xiaohongshu/cookies.json

# 2. 补采详情（断点续传，已采自动跳过）
cd MediaCrawler
DISPLAY=:99 uv run python run_xhs_detail.py --batch-size 40 --cooldown 90 --gap 6

# 3. 清洗
python3 pipeline/clean_cases.py
python3 pipeline/finalize.py
```

清洗与抽检纯本地运行，不依赖网络。数据源路径在 `clean_cases.py` 顶部配置。

## 合规声明

- 本项目仅用于公开信息的行业研究与舆情分析，不涉及任何商业转售、数据售卖
- 采集遵守平台 `robots.txt` 与访问频率限制，单条间隔 6 秒，遇到风控信号（`300013`、`HTTP 461`）立即停止而非重试
- 案例库仅保留公开笔记的正文摘要、互动数与原文链接，已剔除作者内部 ID、设备信息、Cookie 等非必要字段
- 链接中的 `xsec_token` 是平台为笔记生成的**访问签名参数**（用户点击「分享」复制的链接自带该参数），不含账号身份信息、不能用于登录，随笔记公开链接一同分发；移除后部分笔记将无法打开，故予以保留
- 本项目不含任何可登录平台的凭据。复现采集需自备账号，且应遵守平台规则
- 若原作者要求删除相关内容，可提交 Issue，将在一个工作日内从数据集中移除
